   token lengths 2/3/4/5/6 now give separate ranks. A pristine-baseline golden and

   lock. Snapshot-before/drop-after arrangement retains EVERY file in the byte

   QA source-verified the final fix and inspected the implementer's focused
   7/7 Linux rerun (core-windows-snapshot-fix.log); no independent rerun or Windows
   success is implied by that inspection. Await exact-head Windows CI.
4. Benchmark RSS label now explicitly states whole-process high-water memory,
   including fixture indexing and warmup; it is not search-only memory.

Source review conclusions
- No persistent mutation bypass found for read_only lexical or semantic paths.
  Recovery, installation, mutation and corruption-marker verification are
  guarded before work. Sidecar info/coverage use read operations only.
- Read-only handle retains documented Tantivy metadata coordination bookkeeping;
  it is not a promise of a filesystem with all writes forbidden.
- Both MCP mutexes remain. Admission precedes spawn_blocking, and running closures
  retain permits despite cancelled/dropped callers. Started synchronous work is
  not forcibly interrupted. Reserved FIFO maintenance, live metadata reads inside
  workers, and validation before admission from merged PR4 remain intact.
- Same-path source refresh invalidates scans before waiting, including scan-only
  connections. Directory replacement requires close/reopen, not reader.reload.
- Notes and base text use one SQLite read transaction. Current numeric hasMarker
  takes precedence; corrupt compressed/UTF8 bodies error without leaking a
  transaction. Legacy note rendering remains covered.
- Process-global line source remains an ownership constraint; DB/index publication
  is not a cross-file transaction. Stale text is marked and not highlighted.
